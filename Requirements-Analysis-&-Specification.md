# Requirement 1: "The system shall be user-friendly."
## One clarification question 
Who are we making the system "User friendly" for?
## What information is missing?
We don't know who the system needs to be friendly for, what "User friendly" means in this scenario and what percent of users is a reasonable goal.

# Requirement 2: "The system shall notify users about bookings."
## What is the problem?
This doesn't really tell us anything, we don't know who should be getting notified about which bookings.
## One clarification question 
Which users should be getting notified about which equipment?
## What information is missing?
Who specifically needs to be notified about which equipment, what is it notifying a user about in relation to the bookings.

# Requirement 3: "The system shall allow staff to create, edit and delete bookings and send reminders."
## What is the problem?
This doesn't specify which staff memebers should be allowed to do this, what levels do these permissions need to be split by.
## One clarification question 
What staff should have what permissions (e.g. should a staff member who's job is in no way equipment related really be given full permission?)
## What information is missing?
Which staff members should be given these permissions, should this also apply to active booking? (Bookings that are currently in progress), should this be able to overwrite a students pending booking?

# Develop functional requirements
## "The technician needs to know whether equipment is available before confirming a booking"
WHO: The Technician
WHAT: To know if booking is available
WHEN: Before confirming a booking
WHY: So that the technician will not double book equipment
HOW WILL WE KNOW: By inquiring if there has been any issues to do with double booking as of recent
