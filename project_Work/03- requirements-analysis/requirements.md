# Week 3 — Requirements Analysis and Specification
## 1. Information from Week 2
The 3 biggest stakeholders seem to be:

The Organisers who need the system to help them assign Volunteers to work, specify when work need a person of certain skills and need to know the current status of activities (Direct user)

The Volunteers who need a clearer way to communicate with the Organisers, letting the Organisers know when they are/are not able to work, as well as knowing what activities are available and suit their skillset (Direct user)

The local community who need a place for their activities to be seen and assigned Volunteers, the Organisers being able to quickly assign Volunteers of suitable skillsets to these activities will benefit the local community greatly as productivity increases 

## 2. Candidate Requirements
CR01 - The system should allow authorized users to post activities needing help and update those posts as time goes on (This technically has not been confirmed)

## 3. Requirements Surgery
instead of saying that the system should "Be easy to use", we need to be more specific, maybe saying that the system should "Be useable for someone who has been instructed/trained on how to use it to navigate with minimal issue" 

## 4. Functional Requirements
FR01 - The system should have a way to allow Organizers to match Volunteers to an activity 
FR02 - The system should allow organizers to specify when a certain activity needs people with certain skills
FR03 - he system should have a singular area to store data in order to keep it secure 
FR04 - The system should give an option for Volunteers to drop out of an activity, as well as a notification to Organizers when a Volunteer drops out of an activity 
FR05 - The system should allow Volunteers a way to sign in, and new Volunteers a way to register
FR06 - The system should give Organizers a way to see a list of which Volunteers are attending an event/how many Volunteers are attending an event 

## 5. Quality Requirements
QR01 - The system should have an interface that trained users can feel comfortable using and accessing 
QR02 - The system should allow Volunteers to view all of their information that is being stored, and allow them to opt out of certain information being held if they feel is not needed (GDPR Regulations)
